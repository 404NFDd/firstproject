# GeekNews 출처 조사와 NewsHub 디자인 검토

조사일: 2026-10-06, 한국 시간 기준

추가 검토일: 2026-10-07 — 사용자 지정 출처 State of Devs 2026 반영.

목표 반영: 기술 뉴스는 읽을 가치가 있는 소식을 선별하고, 원문에 근거한 AI 요약으로 독자의 관심과 원문 탐색을 유도합니다.

구현 반영(2026-10-07): 목록 중심 화면, 기술 기사 AI 선별·요약 큐, 채택 기사만 노출하는 조건, 카테고리별 수집 요청을 적용했습니다. Nolan Lawson·Mat Duggan·The New Stack의 정상 피드와 본문 필드를 다시 확인해 연결했습니다. 아래의 시안 검증 기록과 구현 전 판단은 조사 당시 기록이며, 현재 구현의 운영 방식은 프로젝트 `CONTENT.md`와 `OPERATIONS.md`를 참고합니다. State of Devs 자동 수집은 발행일 확인 문제로 후보 상태를 유지합니다.

## 결론

기술 뉴스의 목표는 다양한 출처에서 후보를 발견한 뒤 읽을 가치가 있는 소식을 선별하고, AI가 한국어 제목과 짧은 요약으로 핵심과 흥미로운 지점을 전달하는 것입니다. 출처 확대는 좋은 후보를 발견하기 위한 수단이며, 기술 관련 글을 모두 게시하거나 수집량 자체를 늘리는 것을 목표로 삼지 않습니다. NewsHub의 기본 화면은 목록 중심으로 구성하고, 요약과 원문 링크·출처를 분명하게 보여주는 방향을 추천합니다.

2026-10-06 조사 당시에는 앱 구현을 수정하지 않고 출처 조사 데이터와 디자인 검토 시안을 제공했습니다. 조사한 도메인 전체를 수집 대상으로 승인하거나 본문 저장·번역까지 성공한 것으로 간주하지 않습니다. 이후 승인한 구현 내용은 문서 상단에 별도로 기록했습니다.

### 기술 뉴스의 선별과 AI 요약 기준

처리 흐름은 **후보 발견 → 원문 확인 → 선별·중복 제거 → AI 요약 → 근거 확인 → 게시**로 제안합니다. 후보로 발견한 모든 글을 사용자 피드에 노출하지 않습니다.

- 선별: 새로운 변화, 실무 활용 가치, 흥미로운 발견·관점이 있는지 원문으로 판단합니다. 같은 소식의 반복 보도, 내용이 빈약한 홍보, 개인 질문·하소연은 제외합니다. 세부 점수와 게시 수는 구현 검토에서 정합니다.
- 제목: 무엇이 달라졌는지 구체적으로 드러내고, 원문이 뒷받침하지 않는 과장·낚시 표현을 넣지 않습니다.
- 요약: ‘무슨 내용인가’, ‘왜 관심을 가질 만한가’를 2~3문장으로 전달하는 구성을 제안합니다. 단순 번역·본문 앞부분 발췌 대신 원문을 읽고 핵심을 정리합니다.
- 근거: 수치·인용·주요 주장의 맥락을 보존하고, 관심을 끌기 위해 사실이나 효과를 만들어내지 않습니다. 본문 또는 요약 근거가 부족한 후보는 게시를 보류합니다.
- 평가: 게시 건수보다 요약의 정확성, 관심 이유의 구체성, 중복·홍보성 글의 감소를 먼저 확인합니다. 이후 실제 독자의 원문 열람·읽기 반응을 참고하되 과장된 제목으로 반응을 높이지 않습니다.

목록에서는 AI 요약을 중심으로 관심을 판단하고, 원문과 상세 본문에서 더 읽을 수 있게 합니다. 전체 번역 기능의 유지 여부와 별개로 목록의 핵심 가치는 선별과 요약입니다. 이번 목표 변경은 기술 뉴스에 적용하며 일반 뉴스의 정책 변경은 포함하지 않습니다.

### 제공 파일

- `sources.csv`: 도메인별 게시물 수, 조사 섹션별 등장 수, 대표 원문·GeekNews 링크, 피드 확인 상태, 검토 의견.
- `topics.csv`: 116건의 게시물 ID, 링크, GeekNews에 표시된 출처, 등록 시각, 종류, 관측 페이지 ID. Show·Ask도 제외 근거를 확인할 수 있도록 보존.
- `dataset.json`: 조사 범위, 집계, 87개 도메인, 게시물별 근거와 피드 확인 결과를 함께 담은 자료.
- `observations.tsv`: 브라우저에서 추출한 게시물별 원자료. 댓글·요약·기사 전체 본문은 포함하지 않음.
- `feed-checks.json`: 홈페이지에서 발견한 RSS·Atom 주소, HTTP 상태, 피드 항목 수, 본문 필드 길이, 표본 원문 URL의 피드 포함 여부.

CSV는 Excel에서 한글을 읽을 수 있도록 UTF-8 BOM과 CRLF를 사용했습니다. 영문 열 이름은 데이터 처리용이며 의미는 다음과 같습니다.

| 주요 열 | 의미 |
| --- | --- |
| `domain` | www 접두어를 제거한 호스트. 하위 도메인은 보존 |

OpenAI·TechSpot 홈페이지 조회는 HTTP 403이었고, Upstage·Reflection 홈페이지에서는 피드 링크를 발견하지 못했습니다. 이는 피드가 없다는 뜻이 아닙니다. 추가 확인 대상으로 남겼습니다.

일부 표본의 GeekNews 등록일은 최근이지만 피드가 제공하는 원문 시각은 과거입니다. 예를 들어 KCiter 피드의 가장 최근 항목은 2026-07-20, Three Dots Labs 피드의 가장 최근 항목은 한국 시간 2026-08-20입니다. GeekNews 등록일을 원문 발행일처럼 표시하면 이런 글이 새 기사처럼 보일 수 있습니다.

추천 순서는 기존 공식 피드를 유지하면서 본문 필드가 있는 기술 블로그·전문 매체를 검증해 추가하고, summary·description 기반 출처는 실제 본문 추출 기준을 갖춘 뒤 연결하는 것입니다. GitHub·영상·소셜은 플랫폼 전체를 일괄 수집하기보다 개별 프로젝트와 글을 발견하는 경로로 다루는 편이 적합합니다.

화면은 기존 목록 구조를 유지하며 ‘연례 보고서’ 유형, 한국어 제목, 짧은 요약, 조사 기간, 응답자 수, 원문 링크를 표시하는 구성을 제안합니다. 상세에서는 주요 결과를 주제별로 정리하고, 수치를 인용할 때 해당 질문의 응답 수와 원문 도표 링크를 함께 제공합니다. 전체 설문 응답자 수 5,463명을 모든 질문의 분모로 사용하면 안 됩니다. 원문 발행일은 확인될 때까지 미확인으로 표시합니다.

연례 보고서도 출처 확대 범위에 포함하되, 현재 RSS 전용 수집기에 HTML 주소를 넣는 방식으로 연결할 수는 없습니다. 이 기록은 수집 대상 검토에 추가한 결과이며 제품 코드와 자동 수집 설정은 변경하지 않았습니다.

## 3. 현재 화면과 디자인 비교

현재 화면은 코드 기준으로 큰 소개 영역, 많은 카테고리 버튼, 검색·정렬, 수집 버튼, 3열 카드, 기사별 이메일 버튼·선택 체크박스로 구성돼 있습니다. 실서비스의 현재 브라우저 화면은 이번에 검증하지 않았습니다.

| 항목 | 목록 중심 | 요약 카드 중심 |
| --- | --- | --- |
| 탐색 방식 | 여러 제목과 출처를 연속해서 빠르게 훑음 | 각 글의 요약을 먼저 읽음 |
| 구성 | 한 열의 기사 행과 얇은 구분선 | 데스크톱 2열, 모바일 1열 |
| 요약 | 짧은 소개와 펼치기 | 소개를 더 넓게 보여주고 펼치기 |
| 장점 | 글 길이·이미지 유무에 영향을 덜 받음. 다양한 출처를 보기 편함 | 원문을 열기 전에 내용과 맥락을 파악하기 편함 |
| 부담 | 제목·요약 편집 품질이 중요함 | 같은 화면에서 확인할 수 있는 글 수가 줄어듦 |
| 권장 용도 | 기본 뉴스 피드 | 요약을 중심으로 읽는 보조 보기 |

**기본 화면은 목록 중심을 추천합니다.** GeekNews의 정보 밀도와 원문 연결 방식은 참고하되 NewsHub의 브랜드, 분야 선택, 검색, 수집, 이메일 기능을 유지합니다. 투표·댓글·저장 기능은 이번 변경 범위에 추가하지 않는 방향입니다.

### 권장 화면 구성

1. 상단에는 NewsHub 이름, 짧은 서비스 설명, 로그인·구독 등 기존 기능을 간결하게 배치합니다. 큰 소개 영역은 줄여 첫 화면에서 기사 탐색을 시작하게 합니다.
2. 기존 기술 분야를 중심으로 카테고리를 배치합니다. 일반 분야도 접근 가능하게 유지하며 출처 이름을 카테고리 이름으로 사용하지 않습니다. 예를 들어 여러 언론사의 IT 기사가 들어오는 경우 분야 이름은 IT·과학으로 표시합니다.
3. 검색·정렬·뉴스 수집은 보조 도구로 배치합니다. 수집 범위와 보고 있는 카테고리가 다른 현재 동작을 사용자가 혼동하지 않도록 수집 범위를 안내해야 합니다. 카테고리별 수집으로 바꾸는 것은 별도의 동작 변경입니다.
4. 기술 기사 행에는 한국어 제목, 출처 도메인, 분야, 원문 발행일, 관심 이유가 드러나는 2~3문장 AI 요약을 표시하는 구성을 제안합니다. AI가 만든 요약과 원문 소개·발췌는 명칭을 구분합니다.
5. 제목은 원문으로 연결하고, 요약 펼치기와 기존 상세 보기에서 한국어 정리·전체 본문·번역 상태를 읽게 하는 구성을 제안합니다. 상세 페이지를 없애거나 전체 번역을 중단하자는 제안은 아닙니다.
6. 기사 발견 시각과 원문 발행일은 별개로 관리합니다. 원문 시각을 확인할 수 없으면 발견 시각으로 바꿔 표시하지 않고 미확인 상태를 표현합니다.
7. 이메일 선택은 기존 기능을 유지하되 보조 행동으로 둡니다. 모바일은 한 열로 읽으며 작은 글씨·겹친 버튼·가로 넘침을 피합니다.

시안은 목록 중심과 요약 카드 중심 두 가지입니다. 제목과 소개는 출처 조사 결과를 참고해 만든 디자인용 예시 문구이며 실제 AI 요약 결과가 아닙니다. 시안의 검색·분야 선택·정렬·요약 펼치기·기사 선택은 로컬 화면 동작입니다. 수집·메일 버튼은 실제 실행을 하지 않습니다.

## 4. 구현 영향과 확인할 사항

목록을 바꾸는 작업은 주로 `app/page.tsx`, `components/news-card.tsx`가 대상입니다. 상단 소개와 탐색 구성을 조정하면 `components/header.tsx`와 필요한 스타일 일부도 대상이 될 수 있습니다. 기존 상세 읽기와 메일 기능은 유지할 수 있습니다.

한 줄 소개를 진짜 AI 요약으로 바꾸려면 목록 API가 현재 보내는 번역된 소개·본문 발췌와 별도로 검증된 요약을 제공해야 합니다. UI 문구만 AI 요약으로 바꿔서는 안 됩니다. 중요도에 따른 추천도 현재의 정렬 점수와 새 선별 기준을 구분해서 설계해야 합니다.

출처 확대는 `lib/feed-sources.ts`, `lib/feed-news.ts`, `lib/feed-content.ts`, 필요 시 `lib/news-service.ts`에서 검토합니다. 현재의 본문 확보 기준과 번역 처리량을 고려하며, 출처마다 피드가 제공하는 필드의 의미를 확인해야 합니다.

이번에 확인한 것은 출처 링크의 존재, 도메인·게시물 집계, 일부 공개 피드의 응답과 데이터 형태, 디자인 시안의 화면·로컬 동작입니다. 실제 기사 저장, 번역 API 호출, 이메일 발송, 운영 배포는 실행하지 않았습니다.

시안은 데스크톱 1024px, 모바일 390px·320px에서 화면을 확인했습니다. 320px에서 두 안 모두 가로 넘침이 없었고, 카드 화면은 모바일 한 열로 전환됐습니다. 분야 선택·검색 결과 수, 기사 선택, 수집·메일 버튼이 실제 실행을 하지 않는 상태를 확인했습니다. 시안은 제품 코드를 연결한 회귀 테스트가 아니므로 실제 앱의 동작 검증을 대신하지 않습니다.

## 5. 판단을 위한 우선순위

1. 기술 뉴스 후보와 게시 대상을 구분하고, 읽을 가치·중복·광고성에 대한 선별 기준 마련.
2. 실제 원문을 확보하고, 핵심과 관심 이유를 담은 AI 요약의 정확성 검증.
3. 목록 중심 화면으로 제목·출처·AI 요약을 빠르게 탐색하도록 정리.
4. 이번 표본의 기술 블로그·전문 매체·연례 보고서를 검증해 좋은 후보를 발견할 출처 확장.
5. 해외 종합 매체에서도 개발·AI·제품·산업과 직접 관련된 기사부터 선별.

카테고리를 많이 추가하거나 모든 도메인을 한 번에 연결하는 것보다, 실제 원문 확보와 선별 품질을 확인하면서 출처를 확대하는 순서를 추천합니다.
